# Reorganize the Resources Folder

## Status

Completed, descoped, 2026-09-01.

## Outcome

Original outcome called for splitting `system-architecture/` into topic subfolders and filing a loose root-level note. That didn't happen — discussed live and decided the subfolder split wasn't worth touching 20+ inbound links for what was really a "the index reads as messy" complaint. Instead:

- `system-architecture.md`'s index was regrouped into sections (DDIA book / system overviews / reference) — no files moved.
- The DDIA reading hub note was deleted (book finished) and its inbound links repointed, per the now-settled convention: no per-note `Source:` links, one attribution line in the folder index instead (or a section header for mixed folders).
- `behavior-change.md` and `emotional-regulation.md` got the same one-line attribution treatment; `soccer.md` too, while closing out *Soccer IQ* separately.
- `personal-knowledge-management/` was never reviewed.
- The loose `resources/software-engineering/2026-05-28 - JavaScript Dev to Main Merge Review.md` note was never filed.

## Reusable Material

The book-hub-lifecycle and folder-attribution conventions settled during this project are worth reusing on any future book distillation — captured in memory (`feedback_book_hub_lifecycle`) rather than in a vault note.

## Lessons

"Looks messy" doesn't automatically mean "needs restructuring" — reordering an index note fixed the actual complaint at near-zero risk, versus a file-move that would have touched every inbound link for a cosmetic win.
